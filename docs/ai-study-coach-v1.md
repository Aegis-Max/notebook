# AI 学习教练首版规范

## 产品边界

AI 的职责是促使用户主动回忆、自我解释和间隔复习，而不是代写笔记。

首版包含：

- 当前单篇笔记的回忆模式，每轮生成 3～5 道有原文依据的问题。
- 费曼讲解，AI 只指出遗漏、模糊和可能不一致，并继续追问。
- 按答题结果、提示使用情况和信心安排的间隔复习队列。
- OpenAI 兼容云端接口（用户自备密钥）与仅允许 loopback 地址的 Ollama 模式。

首版不包含通用聊天、一键生成总结、全文润色、自动改写笔记、跨章节训练、知识图谱、代码签名、公证和自动更新。

## 主流程

```text
当前笔记
  → 确认本次范围和隐私信息
  → 用户先写总结或明确选择“暂时总结不出来”
  → 冻结笔记快照并隐藏原文
  → 用户逐题作答并先提交信心
  → 按需解锁分级提示或原文依据
  → AI 基于笔记给诊断式反馈和一个追问
  → 薄弱概念进入费曼讲解或复习队列
  → 次日、3 日或 7 日后用变式问题再次测试
```

AI 生成的问题、反馈、答题记录和排期与原笔记分开保存。任何 AI 操作都不得直接修改标题、日期、线索、课堂笔记或总结。

## 反馈契约

“来自你的笔记”只能包含：

- 已覆盖的要点。
- 遗漏内容。
- 模糊表达。
- 与笔记可能不一致之处。
- 一个继续思考的追问。

每条判断必须引用当前复习使用的冻结笔记快照。找不到依据时返回“笔记不足以判断”，不得补造依据。

“模型补充知识”必须单独标注并默认折叠，不参与评分或排期。结构化输出不设置标准答案字段，也不提供把 AI 内容写回笔记的操作。

## 排期规则

| 表现 | 下次复习 |
| --- | --- |
| 错误、想不起来、查看原文、高信心但错误或部分正确 | 次日 |
| 部分正确、使用提示、正确但低信心 | 3 日后 |
| 正确、未使用提示且中高信心 | 7 日后 |

到期日按用户本地自然日计算。下一次复习必须围绕同一概念换一种问法或使用新情境；答错后回到次日。

## 隐私与安全

- 用户主动开始 AI 复习前，不上传任何笔记内容。
- 云端请求只包含当前笔记所需片段，不包含其他笔记、本地路径或无关设备信息。
- 云端密钥只能由 Electron 主进程访问，并使用系统提供的安全存储能力保护；渲染进程只能看到“已配置/未配置”。
- Ollama 地址只允许 `localhost`、`127.0.0.1` 或 `::1`。
- 笔记和模型输出均是不可信数据；输出必须经过结构校验和引用校验，不能执行 HTML、脚本、命令或应用能力。
- AI 失败时，编辑、保存、搜索、导入导出和打印必须继续正常工作。

## 首版发布门槛

- 用户提交初答前，提示、依据和反馈均不可见。
- 每道题和每条笔记型反馈都能定位到有效原文片段。
- 笔记依据与模型补充在数据、视觉和无障碍文本中均有区分。
- 排期规则确定、幂等，暂停、失败和重启不会丢失答案或生成重复记录。
- 密钥不会出现在渲染进程、日志、备份或明文配置中。
- 旧版 v1 笔记备份可以导入；新版备份可以恢复笔记与复习数据。
- 原有笔记功能的测试语义全部保留，并新增 Electron 启动、重启持久化、原生文件操作、安全边界和完整学习流程测试。
- 固定真实模型测试集中，结构和引用校验通过率为 100%，至少 95% 的题目仅凭笔记可回答，正确度判断与人工标注一致率至少 90%，提前泄漏完整答案和敏感信息的样本数为 0。
